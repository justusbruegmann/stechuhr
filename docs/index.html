Backend API for Stechuhr — a time tracking application.

This document describes the API as implemented in the Express routers (auth, userManagement, timeEntriesRoute, requests, notification, summary), the Zod request schemas, the TypeScript types and the database schema. All routers are mounted at the server root by app.ts, in the order: userManagement, auth, summary, timeEntries, notification, requests.

Persistence goes through Drizzle ORM (drizzle-orm/postgres-js); the authoritative table definitions live in drizzle/schema. dbSetup.sql is the original hand-written DDL and may have drifted from it.

Authentication

Protected endpoints expect two headers on every request:

  • authorization — the session token returned by POST /login/
  • userid — the numeric id of the logged-in user

Both are validated by authMiddleware, which also enforces a minimum role. The role required per endpoint is stated in each operation description.

Sessions are valid for 24 hours from creation. The token handed to the client is a 32-character random string; only its hash is persisted, and validation compares the presented token against every unexpired session row belonging to that user.

CORS

A handcrafted CORS layer runs before all routes. Implementing this was necessary because we were unable to configure the cors package to work with PATCH requests while everything else worked flawlessly. Allowed origins are http://localhost:3000, http://127.0.0.1:3000, https://how2centeradiv.dev and https://staging.how2centeradiv.dev; allowed headers are Content-Type, Authorization and userid. Preflight OPTIONS requests are answered with 204 on every path.

Error formats

The API is not consistent about error bodies. Three shapes exist:

  • text/plain — auth, user management, summary and notification routes
  • { "error": "..." } — time entry routes and POST /users/
  • { "code": "...", "message": "..." } — request routes (messages are German)

Known deviations

Behaviour that looks unintended is documented in the affected operation so that this file matches the running code rather than the intended design.

Password

Password and one-time-password management

Change own password (one-time password flow)

Replaces a one-time password with a permanent one. The current password is the only credential checked — this route deliberately runs without authMiddleware so that a user holding an OTP can change it before a session exists.

The new password must be at most 48 characters and must satisfy the service-side complexity rules: at least 8 characters with upper case, lower case, digit and special character.

Get a working time and absence summary

Aggregates worked minutes, holidays taken and sick days for a user over a date range. Allowed if the caller is the target user or their manager.

endDate defaults to today when omitted.
